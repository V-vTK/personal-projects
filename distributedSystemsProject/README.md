# Distributed Systems Project — EHR Platform

A final project for the **Distributed Systems** course at the **University of Oulu**. A microservice-based **Electronic Health Record (EHR)** platform built with a distributed architecture — spanning Spring Boot, Cassandra, gRPC, Flask ML inference, Docker Compose, and Kubernetes. The project descriptions and requirements can be found in the pdf. **The requirements later turned out to be AI-generated by the course staff, which made for some pretty wild specs** — but our group still managed to complete them all.

## Background & Motivation

This project was the final assignment for the Distributed Systems course, where we designed and implemented a distributed EHR platform. The system demonstrates key distributed systems concepts: **horizontal scaling** (Cassandra cluster), **inter-service communication** (REST + gRPC), **service discovery via Docker Compose**, **ML inference as a microservice**, and **audit logging with protobuf-defined contracts**.

The platform allows healthcare staff to manage patient records, researchers to query population-level insights, and a risk-detection ML model to score patient health conditions in real time — all while maintaining an auditable trail of every access and modification.

## Services

### Backend (`backend/`)

**Spring Boot 4.1** application written in **Kotlin 2.3** (JDK 25).

| Layer | Files | Responsibility |
|-------|-------|---------------|
| **Controllers** | `PatientUserController`, `AppUserController` | REST API — CRUD for patients, staff management, population insights |
| **Models** | `PatientUser`, `AppUser`, `ActiveConditions` | Cassandra-persisted entities with `@Table` mapping |
| **Repositories** | `PatientUserRepository`, `AppUserRepository` | Spring Data Cassandra repositories |
| **Services** | `RiskAnalysisService`, `AuditLogService`, `DbBackedUserService` | ML integration, gRPC audit logging, auth |
| **Config** | `SecurityConfig`, `CryptoConfig`, `CassandraConnectionDetailsSelection` | Basic Auth, role-based access, Cassandra connection |

**API Endpoints:**

| Method | Path | Auth Required | Description |
|--------|------|--------------|-------------|
| POST | `/api/patients` | STAFF | Create patient, optionally auto-calculate risk |
| GET | `/api/patients` | STAFF | List/search patients (logs each access) |
| GET | `/api/patients/{id}` | STAFF | Get single patient |
| PUT | `/api/patients/{id}` | STAFF | Update patient conditions (recalculates risk, logs deltas) |
| DELETE | `/api/patients/{id}` | STAFF | Delete patient |
| POST | `/api/staff` | ADMIN | Create staff account |
| GET | `/api/staff` | ADMIN | List staff |
| PATCH | `/api/staff/{id}` | ADMIN | Update staff |
| DELETE | `/api/staff/{id}` | ADMIN | Delete staff |
| POST | `/api/researchers` | ADMIN | Create researcher account |
| GET | `/api/population_insights` | RESEARCHER | Aggregate patient data |

**Security:** HTTP Basic Auth with three roles — `ADMIN` (manage staff/researchers), `STAFF` (manage patients), `RESEARCHER` (population-level queries). Passwords stored as bcrypt hashes in Cassandra.

### Cassandra Cluster

3-node **Cassandra 4.1.2** cluster with keyspace `ehr_keyspace` and replication factor 3. Contains tables:

- `patient_users` — patient records with UUID primary key, name, age, and a map of active conditions
- `app_users` — staff/researcher accounts with username, bcrypt password hash, and role set

### Risk Detection (`risk_detection/`)

**Flask** microservice (Python 3.10) providing ML-based health risk assessment.

- **Model:** Random Forest Classifier (100 estimators, entropy criterion) trained on a [Kaggle health risk dataset](https://www.kaggle.com/datasets/ludocielbeckett/health-risk-prediction-anonymized-real-data)
- **Features:** Respiratory Rate, Oxygen Saturation, O2 Scale, Systolic BP, Heart Rate, Temperature, Consciousness (ACVPU scale), On Oxygen
- **Risk Levels:** Normal (0), Low (1), Medium (2), High (3)
- **Synthetic Data:** Uses CTGAN (via SDV library) to generate realistic synthetic patient data for testing
- **Interface:** REST endpoint `POST /calculate_risk` over HTTPS (self-signed cert)

### Audit Log (`audit-log/`)

Kotlin gRPC microservice for tamper-evident activity tracking.

- **Protocol:** Protobuf-defined gRPC service (`LogService`) with 3 RPCs:
  - `Log(AuditEntry)` — Record an audit event (profile access or condition modification)
  - `QueryActorActions(LogQuery)` — Retrieve all actions by a specific actor
  - `QueryUserHistory(LogQuery)` — Retrieve all actions targeting a specific user
- **Storage:** H2 database via ORMLite with tables `LogEntry` and `ProfileConditionDelta`
- **Audit Events:**
  - `profile_accessed` — logs actor ID, target user ID, and timestamp
  - `profile_modified` — logs the same metadata plus detailed condition deltas (previous → next values per condition key)

## Deployment

### Docker Compose

The main `compose.yaml` orchestrates all services:

- 3-node Cassandra cluster on a dedicated network
- Risk Detection Flask service (port 5001, HTTPS)
- Audit Log gRPC service (port 6767)
- Backend Spring Boot app (port 8080)

Additional Docker Compose files in `deployments/`:

- `deployments/database/docker-compose.yml` — Cassandra cluster only
- `deployments/compute/docker-compose.yml` — Compute services only

### Kubernetes

Kubernetes manifests in `deployments/kubernetes/`:

- `cassandra-statefulset.yaml` — StatefulSet for Cassandra
- `flask-deployment.yaml` — Deployment for Flask risk detection

## Technologies Used
